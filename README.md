# Few-step consistency-model solver for inverse problems (built on PnP-CM)

Working repository (status of 2026-11-24). Full result tables and every experiment: `mode_probe/RESULTS_structured_combinations.md`.
Older write-ups, not updated since 2026-11-21: `mode_probe/PROJECT_SUMMARY.md`, `mode_probe/PHASE_RETRIEVAL_REPORT.md`.

## Idea

Many inverse problems are a linear transform followed by a function applied to each coordinate: `A(x) = f(Tx)`.
In that form the data-consistency step of a few-step solver splits into independent one-number problems that are solved exactly,
so no inner optimiser, learning rate or gradient of the operator is needed.

| Tier | Condition | Data step | Operators |
|---|---|---|---|
| 1 | `T` distance-preserving | one closed-form update | HDR/clipping, quantisation, one-bit, tone curve, JPEG (nearly); every linear task via its SVD |
| 2 | `T` linear with a known decomposition | two closed-form updates (per coordinate, then linear) | nonlinear CT, Poisson CT, blur then clip / quantise, zero-padded and coded-diffraction phase retrieval |
| 3 | neither | reduction to tier 1/2 | nonlinear deblur (network operator), masked phase retrieval |

Components of the sampler (`mode_probe/unified.py`): closed-form data-fit; noise tilted to high frequencies (`TILT=0.5`);
combination of the step outputs and the data-fit image with one weight per frequency band (`lle_fit2.py`, mode `zband8`);
schedule and weights calibrated on images generated by the model itself.
A black-box version of the data-fit needs no formula for a pointwise operator (`GENERIC=1`); `ambiguity.py` flags operators whose
measurements do not single out one answer (wrap-around, magnitudes) and therefore need a starting-point search.

## Known limits (read before quoting numbers)

- One run per method; 107 (CelebA-HQ) and 58 (bedroom) test images. 104 of the 107 CelebA-HQ test images exist in CelebA-HQ itself.
- Some CelebA-HQ settings were chosen on real selection images (one overlaps the test set) or on the test set; they are being redone on
  generated images only (`clean_protocol.py`, `pr_clean.py`; unmasked phase retrieval already redone).
- DPS / DAPS use step sizes borrowed from their face settings; PnP-CM on bedroom uses CelebA-HQ hyperparameters.
- Part of the gap to PnP-CM comes from the shared components (extrapolation / combination, noise tilt), not from the data step alone;
  `attribution.py` isolates the data step.
- On LPIPS, PnP-CM or DPS is better on SR, Gaussian deblur, nonlinear deblur and JPEG.
- Two-piece (tier 2) data steps are exact per piece, not as a joint solve; the phase-retrieval starting stages are iterative (no model calls).

## Two-server workflow

`server_1.md` = jobs for the second machine; it answers in `server1_results.md` (results) and `server2.md` (messages back).

## What is tracked

| Path | Content |
|---|---|
| `mode_probe/unified.py` | the sampler (all tasks, all options are environment variables) |
| `mode_probe/launch_*.sh`, `score_*.py`, `lle_fit*.py` | experiment launchers, scoring, extrapolation-weight fitting |
| `mode_probe/lle/*.json`, `mode_probe/cal/` | fitted extrapolation weights, calibration tables |
| `mode_probe/data_paper/` | the 107 test images (from the PnP-CM paper's validation set) |
| `mode_probe/data100/` | 100 CelebA-HQ images: 0:24 selection, 24:48 calibration |
| `mode_probe/data_gen/`, `data_gen512/` | 24 / 512 images sampled from the consistency model (calibration without real data) |
| `baselines_src/` | our additions to DPS and DAPS: extra operators, CelebA-HQ prior wrapper, job queue, patches |

Not tracked: upstream code (cloned by `setup.sh`), checkpoints, outputs (`mode_probe/exp_*`), logs.

## Set up on a new server

```bash
git clone https://github.com/KheirAli/Few_step-IP-with-DM.git PNP && cd PNP
./setup.sh                                   # clones PnP-CM (pinned), builds the environment, rewrites absolute paths
./sync_large.sh <user>@sfk-srv1.ece.gatech.edu   # checkpoint and large data files (2.6 GB)
```

`requirements_frozen.txt` lists the exact package versions of the original environment (Python 3.11, torch 2.11 / CUDA 12.8).

## Run

Everything runs from `PnP-CM/`:

```bash
cd PnP-CM
# one task, 4 calls, test images 0..53 on GPU 0 (SR as an example)
CUDA_VISIBLE_DEVICES=0 DATA=$(realpath ../mode_probe/data_paper) SHARD=0:54 SAMPLE_SEED=1 RESTART=never NOISE=white NOLOG=1 \
  MODE=unified TILT=0.5 LINEXACT=1 LLE=$(realpath ../mode_probe/lle)/sr_bicubic.json \
  ../pnpcm_env/bin/python ../mode_probe/unified.py fin_demo_sr --deg=sr_bicubic
# output: ../mode_probe/exp_fin_demo_sr_s0/{raw_<i>.pt, stats.json}
```

Per-task options are the `CFG` table at the top of each launcher (e.g. `mode_probe/launch_llepx.sh`).

Current experiments (weights of the extrapolation that vary over the image):

```bash
cd mode_probe
./launch_llepx.sh > logs_x/launch_llepx.log 2>&1     # scalar / 8x8 blocks / per pixel / per pixel and colour, 512 generated calibration images
./launch_llepy_now.sh > logs_x/launch_llepy_now.log 2>&1   # 30 smooth maps / 30-dimensional face embedding (its GPU list GL=(...) puts most jobs on GPU 4; edit)
```

The launchers assume 8 GPUs (`CUDA_VISIBLE_DEVICES=$((g%8))`, 16 jobs at a time); edit those two numbers for another machine.
